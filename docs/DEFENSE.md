# Пам’ятка до захисту лабораторної №8

## Що нового у №8

Сайт узято з №7. Головна робота №8 - історія Git, гілка, злиття, конфлікт, GitHub, clone/push/pull і два хостинги. Створено окремий проєкт, попередні роботи не замінено.

| Термін / команда | Пояснення |
|---|---|
| Git | Локальна система контролю версій |
| GitHub | Сервіс для віддалених Git-репозиторіїв |
| Репозиторій | Файли проєкту та історія змін у .git |
| Working tree | Поточні файли, які редагуємо |
| Staging area / index | Зміни, підготовлені до наступного коміту |
| git status | Показує гілку та стан файлів |
| git diff | Показує відмінності у файлах |
| git add | Додає зміни в індекс; не надсилає їх на GitHub |
| git commit | Фіксує підготовлені зміни локально |
| git log | Показує історію комітів |
| git push | Надсилає локальні коміти на віддалений сервер |
| git clone | Створює локальну копію віддаленого репозиторію з історією |
| git fetch | Отримує віддалені об’єкти й оновлює remote-tracking refs без інтеграції в робочу гілку |
| git pull | Отримує віддалені зміни та інтегрує їх у поточну гілку |
| git pull --ff-only | Дозволяє лише fast-forward; зупиняється, якщо потрібне складніше злиття |
| Branch | Гілка, тобто рухомий покажчик на коміт; дає окрему лінію розробки |
| Merge | Об’єднання історії гілок |
| origin | Звична назва віддаленого репозиторію, а не окрема гілка |
| .gitignore | Не дозволяє випадково додати в індекс нові небажані файли; не прибирає вже відстежувані |
| README.md | Документація: що це за проєкт, запуск, технології, структура й публікація |

## Що реально виконано

- main - основна гілка; feature/release-checklist - окрема зміна документації.
- Той самий рядок docs/merge-demo.md змінено по-різному у двох гілках. Merge створив конфлікт. Обидві перевірки поєднано в одному тексті, маркери прибрано, виконано add і commit.
- Для clone та pull використано другу локальну копію того самого автора. Не заявляємо про іншого учасника.
- Приклади повідомлень: feat: import..., build: configure..., docs: explain..., fix: make....
- У коміті є знімок дерева файлів, автор і комітер, часові дані, повідомлення й посилання на батьківські коміти. Merge-коміт має двох батьків.
- VS Code Source Control: Changes - непідготовлені зміни; Staged Changes - індекс; Graph - історія та гілки.
- M - modified, U - untracked у списку Source Control, D - deleted. UU у короткому статусі Git означає нерозв’язаний конфлікт, а не untracked.
- user.name та user.email записуються в авторство коміту. Це не пароль і не спосіб входу в GitHub. Використано адресу noreply.

## Деплой

GitHub Pages: публічний репозиторій → Settings → Pages → main → / (root). Зміни публікуються після push і успішної збірки Pages.

Netlify: у цій роботі вручну завантажується готовий ZIP із dist. netlify.toml також підготовлено для майбутнього Git-імпорту; автоматичне з’єднання репозиторію з Netlify не заявляється.

Якщо GitHub Pages ще показує 404, перевірити статус збірки та правильну адресу /tviy-hid-lab8/. У repo-site шляхи до assets мають бути відносними.

Перед push: status → diff → add → commit. Перед інтеграцією чужих змін зберегти власну роботу та переглянути отримані зміни. Не використовувати force push без потреби.
